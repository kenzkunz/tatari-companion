# Evolution Trial Planner

Open /evolution-planner.html through Database → Evolution Trial Planner. This noindex account tool uses the canonical public navigation/footer. It replaces the disabled Evolution Trial navigation entry. Authentication and roster/badge reads use the existing Supabase services; the Finish evolution action can save the selected tier through the existing roster RPC. Other planner edits remain local. Goals, entered trial progress and the Wishbox budget are stored only in this browser under an actor-specific key. Auth changes clear visible personal data before loading the next account.

Up to five distinct owned Tatari can be selected. The user can choose any later available form. The route includes all intervening trials. Star copies sum current-star UnitStar costs up to the highest required star threshold, deducting the saved progress toward the next star exactly once. Only the selected Tatari's star upgrades are budgeted. Supporting Tatari star upgrades, event resources and separate acquisition tasks are not included in that number.

Evidence: star-progression.json derives from v0.49.1 UnitStar.lua; roster trial data is audited in EVOLUTION-TRIAL-DATA.md. Item.lua item 1009 describes one chosen purple Tatari. Pet.lua UnitQuality 2 identifies the ten starter families (1–10), which are not eligible for Wishboxes; the other exported families are eligible. No inventory balance is read from the game. No reward forecast is used to predict how long collecting Wishboxes takes.

Exact saved-roster conditions cover food stages, owned elemental Tatari/star counts and saved dojo badges. Counter tasks use manual progress shown in game. A food-rank OR branch can be met automatically when its recorded stage is already attained. Unknown conditions remain manual, never evaluated as executable game code. Completed earlier trials are inferred only from saved evolution; current/future counters are never assumed to carry over. Wishbox acquisition quests are separate from Wishbox spending.

Schedule opportunities use the same published schedule overrides as the Schedule page. Counter 54 maps to Fishing, 53 to the Raft Race skin, 43 to Treasure Hunt, 76 to Cozy Farm and 77 to Zobo Shooter. Energy Drink counters 29/70 map to Gold Rush. Horde requirements use their recovered English label and the existing Horde schedule. Alternate task routes remain alternatives and retain their source conversion ratios. Dates are UTC and may move with future schedule updates; they are opportunities, not promised evolution completion dates. Unscheduled or unknown requirements do not receive an invented date.

Model/client checks: node scripts/evolution-planner-check.mjs, also included through account-check in npm test. Support Tatari budgeting remains a future enhancement.

Upcoming opportunities show target-form playerhead artwork with accessible names and hover labels. When the planner reloads a newer roster, goals whose target tier has been reached are removed and the cleaned goal list is saved locally. Checking manual trial tasks does not update the roster or evolve a Tatari automatically.

Finish evolution opens a confirmation that the player has completed the evolution in game. It reloads the latest account roster, changes only the selected unit tier, and saves with the freshly loaded revision through the actor-guarded roster client. Account level, stars, food, copies, Glitter and other units are preserved. It never downgrades an already-completed goal. Only a successful save (or a roster already at/above target) removes the goal and its local progress. Failed/conflicting writes retain the goal and show an error; duplicate submits are disabled. Auth changes close the dialog and guard stale responses. This reports a player-confirmed game result; it neither performs an in-game evolution nor infers extra stars or food.
